# compromise_heatmap

This project uses Reinforcement Learning agents to generate massive synthetic
intrusion log data for use in training Graph Neural Networks on attack graphs.
The project uses technology produced at the Royal Institute of Technology (KTH)
in Stockholm, Sweden.

## Installation

Before installing dependencies, create a virtual environment:

```
python3 -m venv .venv
source .venv/bin/activate
```

Then, the command below will install most dependencies needed to run the
project:

`while read line; do pip install $line || break; done <requirements.<platform>.txt`

where `<platform>` is either `linux` or `macos`. The above will install
dependencies for the PyTorch backend of the project. If you need to work with
TensorFlow as well you need to install some extra dependencies:

`pip install -r requirements-tf.txt`

Installation of MAL-related libraries is not included in the requirements files
due to them being heavily worked on and git access being almost required.  To
install the MAL libraries:

```
mkdir -p deps
git clone https://github.com/mal-lang/mal-toolbox/ deps/mal-toolbox
git clone https://github.com/mal-lang/mal-simulator/ deps/mal-simulator
pip install -e deps/mal-toolbox
pip install -e deps/mal-simulator
```

One more dependency that is still WIP is the `epic_importer` (a KTH project)
that provides the CLI interface for the app. It is not currently available
publicly and as such is bundled together with the code here under
`deps/twmn-core`:

```
pip install -e deps/twmn-core
```

Finally, you will need a MAL spec and an instance model file. For the expected
format of the latter see [this example](https://github.com/mal-lang/mal-toolbox/blob/main/tests/testdata/simple_example_model.json)

## Project structure

The app is organized in a hierarchical CLI. The entry point is the `./heatmap`
script:

```
./heatmap -h  # or --help
```

This will show the available commands and you can run them with:

```
./heatmap <command>
```

Every command accepts the `-h|--help` flag which will show extensive help for
the command usage.

All commands and module files are **currently** available under the `libexec`
package. Due to this project being WIP there may be unused files in this
package.

## Configuration

Each command accepts a set of arguments and CLI options. To see what a command
accepts, see its help. In addition to the CLI options, the user can provide
a config.yml at the project root that will override any CLI options. This is
counter-intuitive, as the opposite would make more sense, but this is currently
a limitation. For the structure of the config file, see
[config.yml](https://github.com/pontusj101/compromise_heatmap/blob/refactor/config.yml).

## Workflow

There are three stage in the heatmap pipeline: _simulate_, _train_, _animate_
and there are corresponding commands to execute them:

```
./heatmap simulate
./heatmap train
./heatmap animate
```

The code quality of the command scripts (under `libexec/`) follows the above
order.

### Simulate

This stage uses the [KTH simulator](https://github.com/mal-lang/mal-simulator)
to expose the attack graph generated by a supplied MAL spec and instance model
to (currently) simple reinforcement learning (RL) agents to traverse and
compromise. In other projects, the result of a simulation run is to train RL
agents to behave optimally on the graph. In our project, the goal is to generate
synthetic log data. These will be produced by the simulator and be displayed
either in the cli or saved to a file. For more information about this stage see
`./heatmap simulate -h`.

### Train

The goal of this stage is to produce an ML model trained on the synthetic logs
generated in the previous stage. Depending on the configuration file's
`common.backend` setting, either a TensorFlow or a PyTorch model will be
trained. The available GNN architectures to choose from for the trained model
can be found in `tf.py` and `torch.py`. Currently, only one architecture is
available for each and there is no configuration option to switch to another.

### Animate

Animate is the last stage of the pipeline. It uses the trained model to classify
the nodes at each time step of a simulation sample (a file with the results of
a full simulation run). At each time step, the classification of each node from
the model (which is a probability) is taken to colorize graph nodes. The
resulting graph at that time step is dumped to an image. The images of all time
steps are stitched together to produce an animation.

### Syncing online

There is the option to sync produced data and models online on a GCP storage
bucket. See the documentation of each command for the available options. It is
also possible to pull data from the bucket. This syncing is useful for running
training pipelines on services like Vertex AI where local data is inaccessible.

### The `run` script

The run script will execute a full pipeline run starting from producing
simulation results with two different attacker agents up to an animation being
produced. For more information how to use this script, see
[here](https://github.com/pontusj101/compromise_heatmap/blob/refactor/run).


## Docker image

A docker image can be built using:

```
docker built -t heatmap .
```

The resulting image will run the above-mentioned `run` script and can be run,
for example, with:

```
docker run --rm -it heatmap --backend tf --iterations 100 --fp_rate 0.1 \
 --compromised 40 --uncompromised 40 --val-samples 20 --edge-embedding-dim 128 \
 --hidden-layer1 800 --hidden-layer2 1000 --hidden-layer3 1000 --hidden-layer4 \
 500 --epochs 4 --learning-rate 0.0002 --heads-per-layer 2
```

which is effectively the same interface as the `run` script.


The docker image will contain the dependencies for both the TensorFlow and the
PyTorch backends.
